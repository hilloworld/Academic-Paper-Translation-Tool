# 英文论文 PDF 翻译 · 中英对照阅读器

在本地运行的 Web 应用：导入英文论文 PDF → 左侧保留**原始版式**的整页渲染图，右侧以同一张原页图为底、把**按原文坐标落位**的中文译文覆盖上去，左右等分对照、悬停同步定位、缩放联动、翻页滚动同步；翻译走云端大模型（默认 DeepSeek），结果落本地缓存，二次打开不再重复调用。

**图片、表格、公式一律不翻译**：右栏只覆盖可译的正文段落，插图 / 表格 / 公式 / 图表标题 / 参考文献**原样呈现**，不会被中文压住或拆散（见 §5 ⑥-b 与 `docs/preview-*.png`）。

- 后端：FastAPI + PyMuPDF（页面渲染与坐标抽取）+ SQLite（翻译缓存）
- 前端：原生 ES Module，无构建步骤，零前端依赖
- 不联网也能跑（`LLM_MOCK=1` 或 `tools/fake_llm.py`），便于验证链路

### 方式 B：命令行（三步）


## 4. 界面与快捷键

左侧是整页渲染图（公式、图表、排版位置**原样不动**），右侧是同一页的中文译文层。

**右侧的渲染方式（关键）**：右栏**以原页渲染图为底**，只有"会被翻译"的正文片段才用**不透明白底 + 中文**盖上去；图片、表格、公式、图表标题、参考文献这些"按设定不翻译"的区域**不做任何覆盖**，直接把原图透出来——所以公式不会被中文压住、表格的行列结构不会被拆散。

鼠标在左侧移动时，同坐标的片段立即高亮，并出现十字准线；点击弹出该片段的原文/译文对照卡片（可一键复制）。落在图片/表格区域内的片段，会把整个区域一起点亮，一眼看出"这块是原样保留的"。未翻译的正文片段显示为虚线空框（此时下方透出的正是原英文）。

| 快捷键 | 作用 |
| --- | --- |
| `←` / `→` | 上一页 / 下一页 |
| `+` / `−` | 放大 / 缩小（左右等比联动） |
| `Ctrl` + 滚轮 | 以指针位置为锚点缩放 |
| `0` / `9` / `8` | 适应宽度 / 整页 / 100% |
| `T` / `A` | 翻译当前页 / 翻译全部（`A`） |
| `Esc` | 关闭弹层 |

工具栏还提供：**「⚙ 设置」（配置服务商 / Base URL / 模型 / API Key，改完即生效，无需改代码或重启）**、**「重新解析」**（解析逻辑升级后，把已导入的 PDF 就地按新解析器重跑一遍；只重做分块与坐标，**不动译文缓存**——原文没变的片段照样命中）、**「原图底衬」**（默认开启；右栏以原页图为底，图片/表格/公式靠它原样呈现，关掉则右栏只显示译文）、**「溢出全文」**（译文超出原块高度时完整显示而非裁切）、页码范围（`1-14`、`1,3,5-7`、留空=全部）、「重译」（忽略缓存）、「取消」、译文字号滑块（整体放大缩小）、左右栏拖动分隔条、「仅原文 / 左右对照」切换、缓存详情（点状态栏「缓存」，`Alt`+点击清空）。状态栏最左的「模型：…」也是一个设置入口；未配置密钥时会红字提示并自动弹出配置窗口。右栏标题处会显示「本页已译 N/M 片段 · 原样保留 x 图 / y 表 / z 公式」，以及本页有多少片段**自动缩了字**、多少片段**向下延展**。

### 译文放不下怎么办

中文通常比英文长，所以英文段落译成中文后往往比原块更高。程序的处理顺序是：

1. **借用下方空白**：先看该片段正下方到"下一个障碍物"（别的文字块、图、表、公式）之间还有多少空白，能借就借——原段落之间的行距、段末的空当都是可以用的；
2. **自动缩字**：按「真实行数 × 行高 ≤ 可用高度」反解出该片段能用的最大字号（`_fitBlock` 二分搜索），下限 0.55 倍原字号（蓝色虚线框 = 缩过字，通常 0.7–0.9 倍）；
3. **用浏览器真实高度再校一次**：估算与实际排版总会差几个百分点，差值累积起来就会压到下一块上。落版后用 `getBoundingClientRect()` 实测，按「可用高 / 实际高」再缩一次（最多两轮，只会变小所以一定收敛）；
4. **缩到下限仍放不下**：完整显示、向下延展，并加橙色虚线框与提示（`.overflowed`）。**任何情况下都不会把字裁掉**；
5. 想看得更清楚：调大工具栏「字号」滑块，或直接放大页面缩放——左右两栏等比联动，译文框始终贴合原文。

> **行内公式**：嵌在正文里的公式（`x_t`、`σ²`、`|h_t|²`、分式…）在送模型前被替换成占位符 `⟦k⟧` 并记下坐标；模型只需原样保留占位符，前端再按坐标从整页渲染图上裁一小块贴回原位。所以公式永远以原文像素呈现、不会被模型改写，也不会被白底盖住。公式小块**不用 float**——每个 float 都会在右侧挖掉一块行宽，把整段中文挤成细长条。
>
> **段落完整性**：LaTeX 论文里，只要行内出现分式/上下标，PyMuPDF 就会把**同一条视觉行**切进好几个文本块（例如 `MR images {m_t}^T_{t=1} and the actual ...` 会被切成三块）。若照块边界当段落，右栏就会变成一堆互相重叠、语序错乱的碎片。解析器因此多了两步：先按"包围盒是否叠在一起"把碎片聚成连通分量，再把行碎片按几何缝回整行（`_block_components` / `_stitch_rows`），最后才按正文行间距切自然段（`_group_lines`，用行内**非数学部分**的纵向范围算间距，免得被撑高的分式带偏）。

这套机制保证「文字一定完整、且不互相压盖」。

## 5. 关键实现要点

**① 版式保持**：原文层不重排文字，而是 `page.get_pixmap()` 整页位图，任何公式、图表、双栏与行内公式的位置都与原始 PDF 一致。

**② 坐标对齐**：解析时对每个文本块记录 PDF 坐标 `bbox=[x0,y0,x1,y1]`（单位 pt，原点左上）。前端左右两栏共用同一个 `scale`，按下式渲染译文片段，因此缩放任意倍数都严丝合缝：

```
left = x0 × scale      top = y0 × scale
width = (x1−x0) × scale   height = (y1−y0) × scale
```

**③ 阅读顺序**：用简化 XY-Cut（先找完全空白的水平带、再找真正的中缝）递归切分，正确处理「通栏标题 + 双栏正文」这类论文典型版式，保证译文片段顺序与原文一致。

**④ 分块翻译**：按字符预算与片段数上限切块，每块携带 `id`，要求模型回 `{"translations":[{"id":"...","text":"..."}]}`，从而把译文**精确回填**到对应坐标片段；块内并发（默认 4 路）。

**⑤ 缓存**：SQLite 两张表。`translations` 以「提示词版本 + provider + model + 源/目标语言 + 原文」的 SHA1 为键，因此换模型、改提示词自动失效，相同段落可跨页、跨文档复用；`page_index` 记录「文档-页-块 → 指纹」，用于整页快速取回。取译文时会**按当前配置重算键**，所以在「⚙ 设置」里换了模型后，右侧不会继续显示旧模型的译文，而是回到虚线占位框等待按新模型重译。

**⑥ 内容过滤**：按块分类（正文 / 公式 / 参考文献 / 图表 / 图表标题 / 页边 / 页码），默认**只翻译正文**：参考文献、页边 arXiv 水印、公式、图片区域内的文字、整张表格、图表标题都保留原文，避免无意义调用，更重要是避免中文去覆盖公式与图表。

**⑥-b 图片 / 表格 / 公式「原样保留」**：右栏以原页渲染图为底，只有可译片段才用不透明白底 + 中文覆盖，所以"不翻译"的区域天然原样呈现。为此解析阶段要推导出**保留区域**：

1. **找锚点**：识别图题/表题（`Fig. 1:` / `Figure 3.` / `TABLE II:`，要求编号后紧跟 `:` 或 `.`，因此正文里的引用 `Fig. 3 shows…` 不会误判）。
2. **聚图块**：从图题出发，把相邻（≤26pt）的**栅格图块**与**矢量绘图**逐步吞并进来。矢量绘图**不做预合并**——图表动辄上百条路径，提前合并会把整页图纸连成一个 `526×360` 的大框，区域随之吞掉正文（实测踩过）。图题在图下方、表题在表上方，因此生长方向也做了限制。
3. **无框线表格兜底**：booktabs 风格的表没有完整框线，`find_tables()` 检测不出来（实测一篇论文的两张对比表就是）。此时用「行距紧 + 与表题同栏」把标题下方的表格行聚起来——正文行距 ≥9.5pt，表格行距只有 1–2pt，判据很稳；遇到正文行立刻停止。
4. **区域内的文字不翻译**：区域里的 `Power` / `Control` / 刻度值这类标签如果照常翻译，中文就会糊在图上。只吸收"标签型"内容（行距紧、或单双行短文本），**长段落与章节标题永不吸收**，避免区域检测偏大时吞掉正文。
5. **误检防护**：`find_tables()` 会把排列整齐的图表坐标区也判成表格（实测 6 个图区全中）。只有"附近有表题"或"本身落在保留区域里"的检测结果才按表格处理；单元格里超过 150 字的长句一律放回普通块照常翻译——否则正文会被静默地永不翻译。

**⑦ 配置注入**：`界面设置 > 环境变量 > .env > config.json > 内置默认值`。界面保存的项写入 `data/runtime-config.json` 后**就地**刷新进程内的 `Settings` 对象并丢弃缓存的翻译客户端，因此改完立即生效；`/api/config/test` 支持「先试后存」，用待测试的临时配置真发一次请求而不落盘。

**⑧ 译文版式适配**：中文比英文长，硬按原文字号铺进原块必然溢出。前端先算出片段下方可借用的空白，再按**真实行数 × 行高**二分搜索出能落进去的最大字号（`U` 为视觉宽度：CJK 记 1 em、拉丁记 0.52 em；行内公式按它贴出来的像素宽高参与折行），下限 0.55 倍以免小到不可读；落版后再用浏览器实测高度校正一次。**任何情况下都不裁字**——实在放不下就向下延展并标注（橙框）。因为缩放时左右两栏共用同一系数、字号也随系数等比变化，任意缩放倍数下译文框都严格贴合原文。

**⑨ 表格处理**：表格是"版式重灾区"——一行横跨多个单元格，照普通文本块走会把整张表（notation + type + description）拼成一段没有标点的长句送去翻译，译文必然是一坨。因此解析时先用 PyMuPDF 的表格检测（`page.find_tables()`）拿到单元格坐标，把表格**按格拆成独立文本块并各自带坐标**，再按"行优先"排序（先按 y 分桶成行、再按 x 从左到右，避免几十分之一磅的 y 差异把第 3 列排到第 2 列前面）。

**默认「翻译表格内容」是关闭的**：整张表按原样保留（右栏显示的就是原表，行列结构、符号、缩写一个不动），单元格块在页面载荷里被标为 `hidden`，前端直接不渲染。想看中文的表头与说明，在「⚙ 设置」里勾选**「翻译表格内容」**即可逐格翻译（符号/变量格仍自动保留原文，用"是否含元音占比 ≥0.15 的英文词"区分变量名与真英文单词）。这个开关是**运行期**判断的，改完立即生效，不需要重新解析 PDF。

**⑩ 文本抽取质量**（这三条直接决定翻译质量，都踩过坑）：
- **词间空格还原**：IEEE / arXiv 模板常把空格画成独立 span，若按 `sp.text.strip()` 过滤就会丢掉它们，抽出 `CommunicationEfficientRoboticMixedReality…` 这种粘连文本。改为只丢弃真正为空的 span，并用相邻 span 的水平间隙（> 0.22 em）兜底补空格。实测词间空格占比从 0.071 恢复到 0.174（正常英文约 0.15），超长粘连词 790 → 3。
- **公式判据**：旧判据「非字母数字字符占比 > 0.12 即公式」把逗号、括号也算进去，实测把 420 个块判成公式（比正文块还多），导致整段正文不翻译、右侧显示英文原文。改为看「强数学符号/运算符数量 + 英文字母占比」，同一篇论文命中 66 块，原来的真公式一个不落、误判清零。
- **参考文献判据**：旧判据「正文里命中 ≥4 个引用/期刊特征即参考文献」把 30 个正文段落判成了参考文献。改为**按章节识别**——遇到 `References` 标题后其后的块才算参考文献（另加「以 `[n]` 开头」作为兜底），正文里密集出现 `[4]–[6]` 不再误伤。

## 7. 错误处理

- **未配置翻译服务**：首次启动自动弹出「⚙ 设置」并给出填写指引；状态栏「模型」红字提示；点「翻译」时接口返回 400 并说明是缺 Key 还是缺 Base URL / 模型名。
- **保存配置时**：Base URL / 模型名为空、服务商不认识、数值字段非法，都会返回带字段名的中文错误（例如「「温度」的取值不合法」）；`custom` 服务商必须手填 Base URL。
- **切换服务商但没重填 Key**：不会阻塞保存，但会明确提醒「仍在沿用之前保存的密钥，请确认它对新的服务商有效，否则会报 401」。
- **改了渲染倍率**：提醒「需重新导入（或重新解析）PDF 才按新倍率出图」。
- **401 / 402 / 403 / 404 / 413**：分别提示「Key 无效」「余额不足」「无权访问该模型」「Base URL 或模型名不正确」「请求体过大（调小 `LLM_BATCH_CHARS`）」。
- **429 / 5xx / 网络超时**：自动指数退避重试（次数由 `LLM_RETRIES` 控制），仍失败则在任务日志与控制台列出具体错误与页码，**已成功的页面照常写入缓存**，可只重试失败页。
- **模型返回非 JSON**：提示「模型返回内容不是合法 JSON」，并附前 500 字原文便于定位；`LLM_JSON_MODE=auto` 时会先尝试 JSON 模式，接口不支持则自动降级为纯文本模式重试。
- **漏译**：若返回的 `id` 不完整，该页标记为「部分完成」，缺失片段保留虚线框，不会污染其他译文。
- **PDF 非法**：缺少 `%PDF-` 文件头时直接以 400 拒绝，并说明原因。

| **参考文献误判** | 第 1–9 页多处正文段落被判为参考文献而跳过翻译 | 旧判据「命中 ≥4 个引用/期刊特征即参考文献」，而正文里 `[4]–[6]` 这类引用极其常见 | 改为**按章节识别**（`References` 标题之后才算），加「以 `[n]` 开头」兜底。正文误判归零，第 14 页的 42 条真实参考文献正确识别 |
| **译文溢出被裁** | 中文译文比英文长，按原文字号铺不下，右侧文字挤压/被裁 | 译文用了与原文相同的字号 | 新增「按原块尺寸反解字号」的自动缩字（0.7–0.9 倍即可落位）+「溢出全文」开关；第 1 页可译片段 **12 → 16** |
| **表格被拼成一段话** | 表格区域右侧是一大段没有标点、前后不搭的中文；公式/符号全被送去做翻译 | 表格一行横跨多个单元格，按普通文本块走会把整张表的 notation + type + description 连成一条长句 | 用表格检测把表格**按单元格拆块并各自带坐标**，按行优先排序。该论文 6 页的表格从 **6 个巨型块（最长 60 行）→ 116 个逐格块**（默认整表原样保留；勾选「翻译表格内容」才会逐格翻译，且符号格自动保留原文） |
| **图片 / 表格 / 公式被中文覆盖** | 右栏把中文糊在插图上、把表格行列拆成一堆中文长句、公式被译文压住；图里的 `Power` / `Channel` 等标签也被送去翻译 | 原先"不翻译"只是"不渲染文字"，右栏底色仍是白的；图区内的文字标签依旧可译；表格默认逐格翻译 | **改右栏渲染模型**：以原页图为底，只有可译正文才用白底中文覆盖；图片 / 表格 / 公式 / 图表标题 / 参考文献原样透出。图片区域用「图题锚点 + 相邻图块逐跳生长」推导（矢量绘图**不做预合并**，否则会把整页连成一个 526×360 的大框、连带吞掉正文）；图内标签归入区域不再翻译；无框线表格（booktabs）用「行距紧 + 与表题同栏」兜底识别。该论文全篇收敛为 **16 个保留区域 + 91 个图内标签 + 88 个公式**不翻译，可译片段 695 → 509 |
| **表格误检吃掉正文** | `find_tables()` 把图表坐标区判成表格（该论文 6 个图区全中），这些"单元格"一旦按表格处理就会被静默地永不翻译 | 检测结果没有和"表题"这个前提绑定 | 只有「附近有表题」或「本身落在保留区域内」的检测结果才算表格；单元格里超过 150 字的长句一律放回普通块照常翻译。复查全篇：**0 个长句被隐藏** |

顺带修掉：模拟模式（`LLM_MOCK`）产出的占位译文会被写进正式缓存，导致切回真实模型后从缓存返回「【模拟译文…】」——现在模拟结果不入库。

## 9. 已知限制

- 译文长度与中文排版差异无法与原文逐字等高：程序会自动缩小该片段的字号以求落进原文位置（可能到原字号的 0.7 倍甚至下限 0.55 倍），因此小字块里的译文会偏小。想看清就调大工具栏「字号」、放大页面缩放，或勾选「溢出全文」；实在缩不下的片段会完整显示、向下延展并加橙色虚线框提示。
- 缩字只影响该片段的显示字号，**不改变坐标**：左右两栏的对应关系、悬停定位、缩放联动始终精确。
- 扫描版（纯图片）PDF 没有文本层，只能看到原文图、无法抽取片段翻译（需先做 OCR）。
- 公式、图片、表格**一律不翻译**（按需求「展示原图、不要覆盖任何内容」）：右栏以原页图为底直接透出，公式完整、表格行列完整，公式编号 `(1)` 也随公式一起保留；图片区域内的英文标签同样不翻译。
- **保留区域是启发式推导**：绝大多数论文的图题写作 `Fig. N:` / `TABLE N:`，且图题在图下方、表题在表上方，这套启发式很稳；但**图题放在图上方**、或完全没有图题的插图可能识别不到（此时该图的文字标签会被正常翻译并覆盖在图上）。可用 `tools/preview_preserve.py` 生成预览图确认，或直接在「⚙ 设置」里关掉相关开关。
- 表格按 PyMuPDF 的检测结果拆格：含**合并单元格**的表格可能被检测成较大的格子（一个格子里套多行）。默认整表原样保留时不受影响；若勾选「翻译表格内容」，这类格子会作为整体翻译。
- 首次翻译整篇会按页顺序调用模型，页数多时请留意服务商的速率与额度限制；可用页码范围分批翻译。
- 界面设置的密钥以明文存于本机 `data/runtime-config.json`；多人共用的机器建议改用系统环境变量注入，或不用时点「清除界面设置」。
- 配置项（含界面设置）是进程级生效：改了 `PORT` / `DATA_DIR` / `HOST` 这类启动参数需要重启服务，其余翻译参数改完即生效。
- 改了解析逻辑（如本次修复）后，**已导入的 PDF 需要用「打开 PDF」重新导入一次**（或调用 `force_reparse`）才会按新逻辑重新解析；翻译缓存不受影响。
